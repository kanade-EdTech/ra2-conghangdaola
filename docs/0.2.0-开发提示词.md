# 红警 2「从夯到拉」0.2.0 开发提示词

日期：2026-10-13  
目标版本：0.2.0  
配套：[0.2.0 半重构计划](0.2.0-半重构计划.md)  
状态：保留为实施与复核模板；0.2.0 本地实现已完成，实际验证范围见 [验收记录](0.2.0-验收记录.md)。

## 使用方式

完整实施时复制“总提示词”；分次推进时先提供配套计划，再使用对应阶段提示词。以计划为交互契约，以实际文件为实现依据。历史 0.1.0 文档与新计划冲突时，交互采用新计划，业务及平台保留项采用明确的兼容规则。

## 一、总提示词

```text
请在当前红警 2「从夯到拉」项目中完成 0.2.0 半重构：参考 tldraw 的对象直接操作、输入状态机、完成／取消分离和边缘滚动，实现触屏整卡拖动排名。

先读取当前 AGENTS.md、README.md、docs/0.2.0-半重构计划.md、docs/首版验收记录.md，检查已有修改。需要时读取 minitool-zip-builder、toy 与 playwright 技能。保留用户已有工作，不重置工作区，不清理用户真实浏览器草稿。

目标是完整实现、验证并生成两个本地 0.2.0 候选包。沿用原生 HTML/CSS/ES2017 与现有构建，不安装 tldraw SDK，不引入 React，不复制上游实现。参考资料在计划第 2 节；需进一步研究时优先官方文档和源码，区分上游事实与本项目设计。

【产品行为】
1. 整张国家卡片可直接拖动，触摸无需长按或先选中。卡片点按只选中，显示轮廓与“调整档位、前移、后移、移回待排名”入口。
2. 触摸起拖阈值初值 8 CSS px，鼠标／笔 4 CSS px，使用欧氏距离；参数集中定义。
3. 拖动有原位占位、浮动卡片、目标高亮与插入线。可跨档、同档换行重排、移回待排名；有效松手吸附，无效松手回位。
4. 按计划给卡片预先设置 touch-action:none；左侧档位标签和空白保留页面原生滚动。保持单一文档滚动层，保留至少 44px 宽的滚动路径。不在 pointermove 中临时改 touch-action 争抢原生手势。
5. 第二触点加入即取消，等待所有触点释放后重启；不引入自定义双指缩放。异常取消、旋转、切换版本、重置、弹窗、导出与销毁都走统一清理。
6. 键盘和点选操作必须能完成全部排名，不依赖拖拽。选中操作区不推移榜单，触摸目标至少 44px。

【架构与输入】
1. 按计划拆出 input.js、session.js、hit-test.js；drag.js 负责调度与视觉，不读写 localStorage 或直接维护撤销。
2. idle / pressing / dragging / blocked 状态明确，选中项独立。纯状态转换可测；DOM 副作用由控制器执行。
3. Pointer Events 优先，稳定根节点捕获主指针；捕获能力检测与错误回退。仍需跟踪非主触点处理多指取消。
4. 不支持 Pointer Events 时使用 Touch.identifier 跟踪触点及鼠标回退；只安装一套输入适配器，预先处理触摸滚动争用。
5. installDrag 返回 cancel(reason)、destroy()、isDragging()。销毁移除所有根节点、document、window 监听，清除 rAF、计时器、影子及捕获。
6. 统一手势激活入口；兼容 click 去重与当前手势关联，设有效期，新真实按下清除。测试拖完立即再次点击同卡、其他卡和弹窗，不吞真实点击。
7. 鼠标按下到移动保留抓取偏移；触摸可有向上约 20px 的视觉偏移。命中始终使用真实 client 坐标。
8. 命中支持多行，排除拖动项，插入线不改变布局；pointerup 同步使用最终坐标重算目标，不提交旧候选。不能用捕获后 event.target 判断落点。
9. rAF 合并更新，几何读取和视觉写入分批。原卡片保留布局，拖动不整榜重渲染，不保存草稿，不写历史。
10. 边缘滚动按计划的视口、遮挡、时间差及限速规则实现；滚动过程中重新命中。无 visualViewport 时回退，不依赖旧内核缺失能力。

【业务与兼容】
1. 保留 9／10 国名单、国家 ID、五档、图标、标题、导出和两平台适配器。
2. 保留 schemaVersion:1 与 ra2-tier-list:save:v1；0.1.0 草稿直接恢复。选择／手势／影子只存内存。
3. 业务移动仍调用 core.move，经现有 commit 校验后提交。index 是移除源卡片后的目标索引；一次落位最多一条历史，取消及无变化零历史。
4. 两版本独立，标题最多 30 个 Unicode 码点，会话撤销最多 20 次；异常存档保护、存储失败和图片失败处理不退化。
5. 海报只读已提交状态，不包含选择轮廓、影子或插入线。导出前取消未完成拖动。
6. 小红书保持离线、外置经典脚本及相对资源路径，不加入网络、运行时模块、动态执行或 Toy 下载代码；保持 Chrome 61 兼容目标并如实记录未实测情况。
7. 同步构建、打包与产物审计清单，不能仅取消原有 20 文件／8 脚本限制而不建立新的严格清单。明确清理废弃 dist 文件，禁止打入旧模块。

【验证与交付】
按 M0–M4 逐步实施，运行有意义的状态机／几何测试、现有业务回归及真实浏览器触摸事件验证。原生滚动行为不能只靠合成 DOM PointerEvent 断言通过，应使用浏览器触摸输入或真机。
旧“立即弹窗／仅把手拖动”断言随产品行为更新，其余数据保护和导出检查保留。重点覆盖双指、丢失捕获、换行重排、边缘滚动、最终松手坐标、重复结束、连续拖点与控制器销毁。
完成后升级 package.json 至 0.2.0，保留旧包，输出 release/ra2-tier-list-toy-0.2.0.zip 和 release/ra2-tier-list-xhs-0.2.0.zip。
更新 README 和 docs/0.2.0-验收记录.md，附拖动中与落位后的手机截图。记录设备、内核、通过／未测／失败项目；模拟触摸与模拟桥不等同于平台真机通过。
最后交付本地预览、候选包路径、实际验证结果与剩余限制。此次不上传平台或提交审核。
```

## 二、分阶段提示词

### M0：建立可回退基线

```text
执行 docs/0.2.0-半重构计划.md 的 M0。读取项目现状和未提交修改，确认 0.1.0 业务与产物基线。准备独立测试用的 v1 草稿样例，涵盖两版本、部分排名、最长标题和损坏数据；不要操作用户真实草稿。记录保留文件、将替换模块、构建生产清单与现有包信息。运行必要基线检查，报告失败是否与新任务无关。只完成 M0，不提前声称 0.2.0 已实现。
```

### M1：输入与手势状态机

```text
按 docs/0.2.0-半重构计划.md 完成 M1。实现输入适配与纯 session 状态机，统一 mouse/touch/pen，跟踪主指针和所有触点，提供单次完成及幂等取消。实现 Pointer capture 能力检测、Touch.identifier 回退、兼容点击去重与 destroy。先用纯测试证明阈值、取消、双指阻塞、重复结束、下一次真实点击和一次提交规则；随后接入现有 core.move / commit，不改 v1 草稿结构。不为每帧预览写撤销或存档。
```

### M2：整卡直接操作与落位反馈

```text
按计划完成 M2，在 M1 控制器上接入整卡起拖、点按选中与不推移榜单的操作区。重用现有定档面板作为“调整档位”入口，保留键盘完整操作。实现原位占位、浮动卡片、选中轮廓、目标高亮和不参与布局的插入线。提取可测的多行命中规则；空档、行间空白、换行首尾、同档前后、移回待排名均有确定位置。松手重新命中并最多提交一次。提供手机拖动中和落位后截图，实际核查名称、手指遮挡与按钮热区。
```

### M3：触屏滚动与中断处理

```text
按计划完成 M3。验证卡片预设 touch-action:none，左侧标签与空白可原生纵向滚动；使用单一文档滚动层。实现时间驱动边缘滚动，处理底栏遮挡、静止手指、滚动边界、visualViewport 回退与旋转取消。覆盖双指、pointercancel、lostpointercapture、blur、visibilitychange、版本切换、弹窗、导出及 destroy。用浏览器真实触摸输入验证“拖完立即点同卡／另一卡／关闭弹窗”，不要只发合成事件就宣称原生手势正确。手机宽度至少检查 320、375、390、430px；记录实际平台与设备覆盖情况。
```

### M4：兼容回归、版本升级与候选包

```text
按计划完成 M4。回归业务唯一性、两版本隔离、v1 草稿恢复和保护、标题、撤销、重置及海报；保留 0.1.0 的保障，更新已变更的交互断言。同步外部脚本顺序和严格生产清单，运行单元、浏览器及产物审计。确认候选包没有旧模块或开发文件。再将应用版本升级为 0.2.0，按计划生成两个带版本号 ZIP，保留旧发布包。更新 README 与 0.2.0 验收记录，给出预览和截图。现代 Chrome、触摸模拟、B站 App、小红书容器与 Chrome 61 分开记录，不把无法测试的项目写为通过。不执行上传或审核。
```

## 三、独立验收提示词

```text
请以用户验收角度检查 0.2.0 触屏半重构，先读 docs/0.2.0-半重构计划.md，再读实际实现与测试记录。优先找会造成国家丢失／重复、错误档位、滚动卡死、撤销多记、草稿覆盖或触摸误激活的问题。
实际操作完整流程：尤复 10 项 → 从卡片主体拖入最远档位 → 同档换行重排 → 双指中断 → 再次拖动 → 无效区域释放 → 点选换档 → 移回待排名 → 撤销 → 切换版本 → 刷新 → 导出。
同时验证取消后无影子和 rAF 残留、最终松手坐标生效、反复安装销毁无重复监听、旧 v1 草稿不需要迁移。检查两个 ZIP 与对应源码／构建结果一致，发布包中没有开发代码。
列出可复现步骤、实际结果、期望结果及影响；缺少真机或容器时明确写未实测。不要用截图好看或自动测试数量替代交互正确性结论。
```
