## 1. 目标与已确认范围

在现有国家排名基础上，先按原版／尤复分开，再以类别、阵营、科技阶段三个选项确定常规单位的可排序范围。另设按版本独立的 T4 间谍科技榜，通过隐藏彩蛋入口进入；九种国家特色继续两版共用。沿用「夯、顶级、人上人、NPC、拉」五档、触屏整卡拖动、撤销、本地草稿和图片导出，继续输出 Toy 与小红书离线小工具两种包。

用户已确认以下决定，包含对 T4 的补充说明。本文和配套提示词据此修订，后续实施无需再次确认同一范围。

| 确认事项 | 用户决定 | 实施边界 |
| --- | --- | --- |
| 版本是首要边界 | 常规单位榜与 T4 榜均按原版／尤复分开 | 先确定版本，再在该版本内查询；不存在跨版本“全部单位” |
| 科技级别的含义 | 按玩家常用的基础／雷达后／作战实验室后划分 | 本版不提供 TechLevel 数值筛选；原值仅留作数据核对，普通筛选中不出现 T4 或“特殊获取” |
| 单位范围与分类 | 遭遇战常规单位，含国家特色和海空单位；按步兵／地面载具／海军／空中单位筛选 | 常规名单排除 T4；普通建筑不入单位榜，巨炮只在特色榜中保留；不扩展战役、平民及隐藏废弃条目 |
| T4 定义与入口 | T4 指间谍偷取科技后解锁的特殊单位；两版各自独立排序，设帅气的隐藏入口 | 从常规查询、所有“全部”结果及其数量中剔除，独立草稿／撤销／导出；不是原始 TechLevel=4 或 ≥10 |
| 九种国家特色 | 美国伞兵、狙击手、巨炮、坦克杀手、黑鹰战机、磁能坦克、辐射工兵、恐怖分子、自爆卡车；原版与尤复共用一份特色榜 | 共用标题、排名、档内顺序及会话撤销；不按游戏版本复制特色草稿 |

其他本次设计决定：阵营指盟军／苏军／尤里，不等同于九国；筛选条件之间取交集；国家榜和 T4 榜各按版本、常规单位榜按版本和组合独立排名，特色榜跨版本共用；首次进入所有卡片均在待排名区，不预填作者强弱评价。版本号 0.3.0 是本次新增功能的建议编号。

## 2. 已核实的基线与数据缺口

### 2.1 应用现状

- `src/data.js` 定义两版国家、阵营和五档；原版九国、尤复十项。
- `src/core/ranking.js`、`src/core/storage.js` 当前仅支持按版本保存两张国家榜，存档为 `schemaVersion: 1`，键为 `ra2-tier-list:save:v1`。
- `src/app.js`、拖拽输入模块和海报依赖 `countryById`、`data-country`、国家名称与国旗尺寸。加入单位需要抽出通用“排名项目”，不能仅增加数组。
- 0.2.0 已实现整卡直接拖动、点选操作、边缘滚动、多指取消、一次落位一次撤销。此次复用这些行为，不另写一套单位拖拽。
- 构建和审计明确列举生产文件及外置脚本顺序，现有未压缩产物预算为 2 MiB；这属于项目预算，不是本次重新核实的平台上限。
- 当前图片导出宽度为 1080／720px，像素上限为 4,000,000，按国旗比例绘图；需要支持 60×48 单位图标和更多卡片。

## 3. 用户入口与榜单行为

### 3.1 三个常驻入口与 T4 隐藏入口

| 入口 | 内容 | 默认标题 |
| --- | --- | --- |
| 国家榜 | 保留原版 9 国、尤复 10 项 | 国家强度排序 |
| 单位榜 | 当前版本内按下列三个条件组合得到常规单位名单，始终排除 T4 | 根据条件生成，例如“盟军步兵强度排序” |
| 国家特色榜 | 两版共用的固定九种特色，卡片同时标注国家与特色名称 | 国家特色强度排序 |
| T4 隐藏入口 | 当前版本的间谍科技单位，独立于常规榜 | T4 间谍科技强度排序 |

原版／尤复版本选择是国家榜、常规单位榜和 T4 榜的顶层边界，进入 T4 后仍可切换版本，切换即恢复另一版本的 T4 榜。进入特色榜时收起版本切换，显示“原版／尤复共用”。单独记住最近选择的游戏版本，离开特色榜后用于恢复版本相关榜单，不能因特色榜没有版本而默认为原版。首次打开沿用国家榜；迁移后恢复旧草稿的版本。此后恢复最近使用的榜单及筛选条件。

### 3.2 单位榜筛选

| 维度 | 可选值 | 规则 |
| --- | --- | --- |
| 类别 | 全部／步兵／地面载具／海军／空中单位 | 面向玩家的类别；用标签表达必要的交叉身份 |
| 阵营 | 全部／盟军／苏军／尤里 | 原版没有尤里阵营选项；来自原版的尤里相关单位按其该版身份分类 |
| 科技阶段 | 全部／基础／雷达后／作战实验室后 | 按最低解锁阶段精确筛选；“雷达后”不额外包含基础单位；“全部”也排除 T4 |

操作顺序为“先选游戏版本 → 设置类别、阵营、科技阶段三个选项 → 应用条件开始排名”。三个维度分别单选，可自由交叉；界面按类别、阵营、科技阶段排列。每个维度的“全部”仅表示不限该维度，不能越过游戏版本边界或纳入 T4。查询顺序先锁定版本与常规名录，再取三个条件的交集。须覆盖以下用法，而不是只提供几个预设榜单：

- 某阵营某类：盟军步兵、苏军地面载具、尤里海军。
- 某科技阶段某类：所有阵营的基础步兵、雷达阶段的空中单位。
- 三项交集：尤复 × 苏军 × 空中单位 × 作战实验室后。
- 单一条件或三项不限：本版全部常规海军、本版全部尤里常规单位、本版全部常规单位；均不跨游戏版本且不含 T4。

T4 不作为普通科技下拉中的第四级或“特殊获取”选项出现，也不混入“全部阶段”“全部类别”“全部阵营”及三项全部的结果。常规单位数量、已排进度、待排名区、重置名单和导出均只使用筛选后的常规集合。T4 名单与入口见第 3.4 节。

手机上让顶层版本选择清晰可见；三个单位选项同置于一个可折叠面板，收起后显示条件摘要及常规单位数量。修改面板条件只预览数量，点击“开始排名／应用条件”才切换榜单，避免每点一下就生成草稿。国家榜、特色榜和 T4 榜不显示常规单位筛选面板。

无匹配时显示“这个组合暂无单位”，可清除条件；不生成空草稿、不允许导出，不把零项显示为 100% 完成。仅一项时允许正常排名和导出。

切换版本时保留仍有效的单位筛选；若从尤复的尤里筛选切到原版，阵营恢复“全部”并说明“原版没有尤里阵营，已显示全部阵营”。先取消正在进行的拖拽，再执行切换。

### 3.3 排名是否共用

国家榜按版本独立保存；单位榜按“版本 × 规范化筛选组合”独立保存标题、档位和顺序。例：“盟军全部常规单位”和“盟军常规步兵”是不同榜单，即使含有相同单位，也不自动同步评分。切回组合恢复原排名，重置仅作用于当前组合。

国家特色榜始终是同一张共享榜：从任一游戏版本进入，都恢复同一个标题、排名、顺序和撤销栈；重置作用于这张共享榜并可撤销。特色项目与对应的国家项目、单位项目仍独立评分。共用是一份综合个人评价，不要求两版游戏数值或强弱完全相同。

T4 榜按版本独立保存，且与该版本常规单位榜隔离；进入时展示该版全部已核实 T4，不继承普通榜的类别、阵营或科技筛选。关闭 T4 返回该版本上次应用的常规单位组合，恢复标题和排名；两版分别记住最近的常规筛选，不用默认值覆盖。

标题自动生成只发生在新榜单创建时；已有自定义标题不因切换、返回或文案升级而改变。标题继续限制为 30 个 Unicode 码点。

本版不增加全局实时搜索，以免引入“搜索隐藏的卡片如何参与拖动和导出”的第二套语义。若后续需要查找单位，作为独立交互设计。

### 3.4 T4 机密档案：独立榜与隐藏按钮

T4 的产品定义已经确认：间谍偷取科技后解锁的特殊单位。只纳入本版本实际可获得的此类单位；逐版核对，不依据强度猜测、数值 TechLevel、游戏 ID 的跨版本同名或单个规则标记直接生成名单。例如 YURIPR 在两版本中的身份和获取条件不同，必须分别判断，不能全局将该 ID 都标成 T4。最终名单和数量在 M1 名录审核中确定，不在本计划里凭印象硬编码。

**入口设计：**常规单位筛选面板外侧、靠近条件摘要的右下角放一个低调的“机密档案”徽章，面板折叠和零匹配时仍可进入。它不占用常驻榜单标签或科技选项；尺寸至少 44×44px，以深色金属底、琥珀色警戒斜纹、暗红封签和小型档案／锁形图案呈现。图形使用本地 CSS／SVG，贴合现有红警视觉。

点按徽章后展开一张“封存档案”小面板：封签裂开、细扫描线扫过，约 180–240ms 后显露醒目的“T4 · 机密科技”与“进入 T4 排名”按钮。简短说明为“间谍科技单位 · 独立排名 · 不计入常规榜”，同时显示当前游戏版本。特效只在主动展开时播放，不循环闪烁、不播放音效；用户偏好减少动态效果时直接显示最终状态。这个展开过程是彩蛋表现，不是认证或权限验证。

隐藏指低调、探索式入口，不能依赖只有开发者知道的多连击或强制长按。徽章可通过键盘聚焦并用 Enter／Space 打开，提供“打开 T4 机密档案”的可访问名称及展开状态。关闭面板后焦点回到徽章；没有 hover 的触屏也可完成全过程。展开动作取消当前拖拽但不产生排名历史，切模式、切版本或离开页面时清理面板和动画。

进入后显示独立 T4 标题、当前版本、“独立榜”标记及“返回常规单位榜”按钮；复用完整五档、触屏拖动、撤销、重置及导出。没有核实出可纳入单位的版本显示明确空状态，禁用排名和导出，不借用另一版填充。刷新可直接恢复最后访问的 T4 榜，无需每次重新点彩蛋。T4 默认无类别／阵营／科技子筛选，整个本版 T4 名单就是排序范围。

验收以“展开前低调、展开后明确、手机上容易点击、返回不丢排名”为准，并提供徽章、展开效果和 T4 榜截图；不能只增加一个写着 T4 的普通文字按钮就视为完成视觉要求。

## 4. 单位名录整理规范

### 4.1 保留原始清单，新增产品名录

已有 `assets/unit-icons/*/manifest.json` 是采集档案，保持原始信息；另建经过整理的产品名录与人工修正规则，不在清单中覆写原名、伪造阵营或直接删掉遗留条目。

为两个版本的每个登记单位建立处置记录：纳入／排除／待核对及原因。按 `version + gameId` 标识，不用图标哈希或显示名称当单位 ID。共享图标不等于同一单位，不同游戏版本同 ID 也可能代表不同身份。

建议生产字段：

| 字段 | 用途 |
| --- | --- |
| itemId、version、gameId | 稳定身份；例如 `unit:yr:SNIPE` |
| displayName、sourceName、aliases | 面向用户的简体名称、原始名称、可选别名 |
| sourceCategory、categoryTags | 保留引擎登记类型，另给玩家分类标签 |
| factions、countryRestrictions | 已核对的阵营身份与国家专属条件 |
| techLevelRaw、techStage、acquisition | 原始数值、玩家阶段、普通生产／间谍科技等获取方式 |
| rankingPool | `regular`／`t4`／`excluded`，按版本决定常规、T4 或不收录；纳入状态仍由审核记录约束 |
| prerequisiteRaw、classificationEvidence | 原始前置及分类理由，后者留在开发数据中 |
| normalIcon、eliteIcon | 普通图标与可选三星图标 |
| inclusion、reason | 纳入状态与原因，生产包只输出需要的字段 |

生产数据编译为外置经典脚本，运行时不读游戏 MIX、不联网拉数据、不用 fetch 加载 JSON。未来在另一台机器构建时使用已提交的整理数据即可；只有重新采集时才依赖本机安装路径。

### 4.2 纳入边界

- 默认纳入本版遭遇战有明确获得途径的常规战斗、生产、运输、采矿、工程等单位；国家专属单位既进入相应单位榜，也以独立特色项目进入特色榜。
- 间谍科技单位核对实际条件后仅纳入该版 T4 名录，`rankingPool=t4`，不进入常规查询，`techStage` 不伪填为普通三阶段；原始条件留作来源依据。仅有 TechLevel 非负或菜单图标不足以证明可获得。
- 默认排除战役限定、平民、无生产意义的替身、弹体、舰载子机等派生物、废弃或不可获得条目。把理由列入审核表，分别核对常规榜与 T4 榜的完整性，避免应收录单位漏入两个名单之外。
- 无普通图标且候选确实应纳入时，列为待处理问题，采用明确文字占位方案或补采真实资源；不悄悄排除，也不借用无关图标。
- 三星图标表示同一单位的等级，不作为第二张单位卡。本版使用普通图标，三星素材继续保留在源素材库。
- 两版同名但身份不同的单位分别核对，例如 YURIPR；多阵营工程师／军犬按独立游戏 ID 保留，并以阵营短标签区分。

### 4.3 阵营、类别、阶段的判定

1. 扩充只读规则提取，读取 Owner、RequiredHouses、ForbiddenHouses、TechLevel、Prerequisite／覆盖字段、Naval、MovementZone、Jumpjet、ConsideredAircraft、SpeedType、BuildLimit、全部 RequiresStolen*Tech 字段及相关生产条件。缺失值保持“未定义”，不一律填默认。
2. 由 Owner 与国家限制得到候选范围，再结合本版正常生产链和人工复核确定阵营身份；不能仅靠 Owner，也不把占领敌方建筑后理论可造解释成所有阵营共享。
3. 分类采用标签：步兵身份与空中身份允许交叉，火箭飞行兵可进入两个分类；一次查询对 itemId 去重。基洛夫、飞碟、武装直升机归空中；航母、无畏、海豚、巨型乌贼归海军。两栖能力本身不自动等于海军。
4. 阶段以本阵营正常生产链为依据，展开 RADAR／TECH／BARRACKS 等别名及必要前置建筑链；不能仅做字符串包含判断。盟军空指部、美国空指部、苏军雷达、尤里心灵探测器的作用需分版核对。
5. 前置链中的“同时需要”与别名组中的“任选一种”分开处理，处理循环／未知节点，不无限递归。国家专属分支只使用合法国家路径，不由占领路径降低阶段。
6. 对遥控坦克控制中心等非三层标准结构，提供明确映射依据；无法确认的条目保持待核对，不能默认为基础或忽略。
7. 将 TechLevel 原值保存为独立核对字段，本版不提供数值筛选；界面只提供已确认的科技阶段。阶段筛选表示最低解锁阶段恰好等于所选阶段，不累计包含更低阶段。

显示名称以项目采用的简体名称表为准，保留原始繁体／英文名称用于溯源。不能直接全局替换导致不同单位重名或不同版本混淆。

## 6. 通用排名与草稿结构

### 6.1 业务核心

引入统一项目解析器 `getItem(itemId)`、名录查询 `getEligibleItemIds(context)`，让排名核心面向当前允许的项目集合，不再内置“版本对应国家数组”。界面、可访问性文案、弹窗、拖拽、撤销及导出共同使用同一项目解析器。

- 当前榜中每个允许项目恰好出现一次：五档与待排名区的并集等于该榜允许集合。
- 拖动继续只在松手提交；索引继续表示移除源卡片后的目标插入位置。
- 一次有效变化只记一条历史；取消、无变化和筛选预览不记历史。
- 撤销按榜单键独立，单榜最多 20 次会话历史；不将历史写入持久存储。
- 特色榜使用唯一共享键，两个版本入口指向同一份草稿和撤销栈，不能通过复制或双向同步两张榜来模拟共用。
- 切换版本、模式或已应用条件时，先处理标题编辑和当前保存，再取消拖拽、清除选择，恢复目标榜；输入法组合输入期间不得截断标题。
- 拖拽会话绑定完整榜单键，而非仅 version。旧榜的延迟 pointerup 不能写入新榜。
- T4 与常规单位沿用版本化 `unit:<version>:<gameId>` 身份，由 rankingPool 决定可进入哪个模式，不另造虚假单位。每版常规集合与 T4 集合必须无交集；两版同 gameId 可以有不同归类。

### 6.2 建议存档 v2

新键：`ra2-tier-list:save:v2`，`schemaVersion: 2`。应用 0.3.0 与存档 v2 是两个独立版本概念。

示意结构，字段最终命名可在实施时统一，但隔离和兼容规则必须保持：

```json
{
  "schemaVersion": 2,
  "catalogRevision": 1,
  "lastGameVersion": "yr",
  "activeBoardKey": "yr|units|allied|infantry|stage:radar",
  "boards": {
    "yr|units|allied|infantry|stage:radar": {
      "context": {
        "version": "yr", "mode": "units",
        "faction": "allied", "category": "infantry",
        "tech": { "kind": "stage", "value": "radar" }
      },
      "title": "盟军雷达阶段步兵强度排序",
      "tiers": { "hang": [], "top": [], "elite": [], "npc": [], "la": [] },
      "unranked": ["unit:yr:SNIPE"]
    }
  }
}
```

上例只展示结构，不是完整允许名单。国家榜键为 `<version>|countries`，特色榜固定为 `shared|signatures`，T4 榜为 `<version>|t4`；常规单位榜按固定顺序编码版本与三个规范化条件。无科技筛选统一编码为 `tech:all`，具体阶段使用 `stage:<stageId>`，本版不生成 TechLevel 数值筛选键。键来自已验证枚举，不能直接由用户标题拼接。

T4 context 为 `{ "mode": "t4", "version": "ra2" }` 或 yr，规范化时移除普通单位筛选字段；查询只能读取该版本 rankingPool=t4 的已纳入项目。增加按版本保存的 `lastRegularContexts` 导航字段，记录每版最近应用的常规筛选，返回时恢复对应榜，不由 T4 模式反写它。彩蛋是否展开、动画进度不持久化；activeBoardKey 可以是 T4，以便刷新恢复。

特色榜 context 固定为 `{ "mode": "signatures", "scope": "shared" }`，不含 version、阵营、类别或科技筛选；规范化时移除这些不适用字段。其项目 ID 为 `signature:america` 等九项。`lastGameVersion` 在进入特色榜时保持不变，刷新恢复共享榜也不丢失返回国家／单位榜所需的版本；它只用于界面导航，不参与特色榜的查询、存档键或导出说明。

按需建立榜单，不预生成所有组合。预览筛选不保存；未编辑的空白榜无需永久堆积，仍应单独保存最近上下文以便恢复。持久化只存 ID、条件和排名，不复制名录、图标或图片 Base64。配额不足时明确提示本次编辑未持久化，不静默删除其他榜单。

### 6.3 v1 迁移与保护

1. 优先读取 v2；只在 v2 不存在时读取 v1。v2 损坏或版本更新时不得回退旧 v1 覆盖它。
2. v1 两张国家榜迁入两个国家榜键，保留标题、档位和档内顺序；将 activeVersion 转为 lastGameVersion，并恢复对应国家榜。可保留原国家 ID，以免无必要地改变已有数据身份。v1 没有特色榜，后续首次进入时只新建一张共享特色榜。
3. 精确匹配已有旧默认标题时，继续迁成“国家强度排序”；用户自定义标题与允许的空标题保持原行为。
4. 迁移先在内存完成、校验，再写入 v2；成功写入后才视为持久化完成。v1 原键保留，不删除、不回写；失败时提示并保留原数据，重复迁移必须幂等。
5. v1 无法读取、v2 损坏或未来格式时，沿用保护存档原则，不用新空榜静默覆盖异常原文。
6. 名录修订时，为已知旧目录提供明确迁移：保留仍合法项目的档位和顺序，新增项目加入待排名；移除项目的历史需留可恢复备份并提示。未知 catalogRevision 先保护，不能套用“去掉不认识的 ID”清空用户结果。
7. 读取对象仅接受允许字段与键，拒绝危险对象键和无效条件；限制异常输入规模。此处延续现有损坏草稿保护，不增加账号或云存储。

## 7. 卡片、触屏和大名单体验

- 国旗保持原比例；单位和特色图标保持源比例，60×48 图标不能沿用国旗的扁长绘制尺寸。像素图采用清晰缩放，图片加载失败时显示可辨识的名称占位。
- 名称允许合理换行；工程师等同名项目加阵营标识，国家特色加国家标识。不同高度的名字不应令命中区域跳动。
- 继续整卡起拖、点按选中、操作区定档／前移／后移／移回待排名；触摸目标至少 44×44 CSS px。
- 统一从 `data-country` 迁为通用项目标识，检查输入适配、幽灵卡清理、焦点恢复、选择样式和测试脚本，不能只改页面渲染。
- 沿用一层文档滚动和明确的空白／档位标签滚动路径。拖拽时不整榜重绘，按帧更新预览，边缘滚动考虑底部操作区遮挡。
- 最大已确认名单下检查多行待排名、最远档位、跨行顺序、同图标不同 ID、长名称和视口旋转。先测量真实性能；未发现瓶颈前不引入列表虚拟化或新框架。
- 拖动与点选提供同等完整操作；空结果禁用排名动作和导出。重置确认明确指出当前版本及条件，保留标题并可撤销。

## 8. 海报与平台产物

海报使用当前榜单快照，不读取 UI 临时筛选或未提交拖动。国家／单位榜展示标题、游戏版本、榜单类型、适用的筛选摘要、已排数量／总数；特色榜显示“红警 2／尤里的复仇 · 共用特色榜 · 9 种国家特色”，卡片同时显示国家名与特色名，不带单位筛选条件或最近访问的单一版本。分享图必须能独立说明排名对象。

T4 海报明确写“原版”或“尤里的复仇”及“T4 间谍科技 · 独立榜”，不显示普通榜遗留的筛选条件；普通单位海报不得含 T4 卡片或把 T4 计入分母。两者分别按各自允许集合生成，不通过临时 CSS 隐藏卡片来伪装分离。

按当前名单加载图片并缓存，限制并发，避免重复加载整个素材库。导出前预估尺寸，先检查像素预算再分配完整画布；单张超限时明确提供 720px 轻量导出。若最低支持宽度仍超预算，再按完整卡片行分页，保持五档及档内顺序，重复必要的标题／条件／档位标记，标注页码；不得靠丢弃未排名单位、截断卡片或缩成不可读文字解决。分页逐张生成和释放画布，允许逐张预览与保存。

Toy 保留现有浏览器保存路径；小红书使用现有宿主桥保存，没有能力时提供图片预览和系统截图路径。批量多图权限与能力未实测前不承诺一键全部保存。异步导出绑定启动时的榜单快照，完成后不得覆盖另一榜的标题或草稿。

构建仅复制实际引用的普通单位图标、特色图标和国家国旗。`raw/`、完整 cameo 库、三星图标、CSV、来源绝对路径、采集脚本、测试和文档不进入平台包。允许按哈希去重二进制资源，但单位身份和版本数据仍独立。

两个版本普通单位 PNG 合计约 720 KiB，精简打包有条件沿用现有 2 MiB 未压缩预算；这只是可行性依据，最终以完整产物测量为准。先去除未引用资源，再评估预算变更，不直接取消检查。

保持本项目现有离线、相对路径、外置经典脚本、ES2017／Chrome 61 兼容目标和两平台适配隔离；构建与审计从同一资源清单得到严格文件列表，缺文件和多余文件都应失败。真实平台限制以实施时使用的适用技能和实际审计为准。

## 11. 验收清单

### 数据与筛选

- [ ] 所有原始登记单位均有纳入／排除记录；不把采集数量冒充可用单位数量。

- [ ] 首先锁定游戏版本；三项全部仍只返回本版常规单位，列表、数量、进度、重置和导出均排除 T4。
- [ ] 原版和尤复 T4 分别按实际获取条件审核，常规／T4 集合每版无交集；不按 TechLevel 数值或跨版同 ID 猜测。
- [ ] 基洛夫／飞碟等进入空中榜，舰船／海洋生物进入海军榜；交叉标签不造成同榜重复。
- [ ] 工程师、军犬、国家专属条件及两版同 ID 不同身份均核对。
- [ ] SNIPE 数值与阶段区分、TTNK 雷达条件、原版／尤复间谍科技均有依据。
- [ ] 两版本入口进入同一张特色榜，全局恰好九个特色项目；美国使用 APARICON，法国巨炮可正常排名。
