# 原版与尤复单位图标采集

采集日期：2026-10-13。素材已保存到 `assets/unit-icons/`，可通过 [本地图标素材库](单位图标素材库.html) 浏览。

## 采集结果

| 项目 | 红警 2 原版 | 尤里的复仇 |
| --- | ---: | ---: |
| 配置登记的步兵／载具／飞机 ID | 109 | 157 |
| 有普通菜单图标的单位 ID | 64 | 94 |
| 有独立三星菜单图标的单位 ID | 36 | 60 |
| 没有定义普通菜单图标的单位 ID | 45 | 63 |
| 有普通菜单图标的建筑 ID | 67 | 84 |
| 完整菜单图标文件名 | 203 | 270 |

“单位 ID”包含战役、隐藏、替身和载机单位，不等于遭遇战可生产单位数量。不同单位可能共享同一图标，清单仍按游戏 ID 分别记录。例如多个工程师、狗及特殊战役单位存在共享资源。

原版 `cameo.mix` 有 203 个图标文件；尤复 `cameomd.mix` 有 70 个，其中 3 个文件名覆盖原版，合并后的尤复版本为 270 个。保留每个版本实际采用的资源，不用尤复图标覆盖原版文件夹。

## 文件组织

```text
assets/unit-icons/
  collection.json                总来源、档案哈希和转换方式
  ra2/                           红警 2 原版
    manifest.json                单位、建筑与完整图标索引
    units.csv                    可用表格软件打开的单位索引
    units/<单位ID小写>.png       普通单位图标
    units/elite/<单位ID小写>.png 三星单位图标
    buildings/                   建筑图标，含已定义的三星变体
    cameos/                      完整菜单图标及多帧素材
    raw/                         原始 SHP 与 cameo.pal
  yr/                            尤复；同上结构
```

PNG 采用游戏原始尺寸，不裁切文字、边框或更改颜色。正常红警单位图标通常为 60×48。完整菜单库还包含其他尺寸及历史遗留图标；多帧 SHP 除首帧外生成 `-frame-2.png` 等文件，原始帧始终保留在 SHP 中。

`manifest.json` 包含游戏 ID、游戏中文名称、内部名称、Image ID、类别、Owner、科技等级、前置建筑、普通／三星图标路径、来源档案、原始 SHP／输出 PNG 哈希及调色板信息。中文名称直接读取安装包 CSF，保留其中的繁体或英文，不自行翻译成另一套名称。

## 来源与版本判定

只读取 `D:\Red_Alet_II\YURI` 中的以下游戏档案，没有使用 Mental Omega 等 MOD 目录，也没有改动安装文件：

- 原版：`ra2.mix` 内的规则、图像配置和 `cameo.pal`；`language.mix::cameo.mix` 的图标与 `ra2.csf` 名称。
- 尤复：`ra2md.mix` 的配置，加 `expandmd01.mix` 的 `rulesmd.ini` 补丁；`langmd.mix::cameomd.mix` 覆盖同名图标，名称使用 `ra2md.csf`。
- 文件名辅助索引：本机 `D:\Red_Alet_II\Utilities\global mix database.dat`。最终按 MIX 文件名哈希匹配资源，而非仅根据文件名猜测存在性。

资源包的完整 SHA-256 位于 `collection.json`；每个图标的具体内层来源位于版本清单。安装包来源没有外部官方签名核验，因此应理解为“本机原版／尤复资源”，不把它称为已认证官方发行包。

## 没有图标与缺失引用

全部已找到的单位普通 Cameo 引用都成功提取；无普通图标的项目在单位记录中标为 `not-defined-in-art`。这些包括大量平民、动物、民用车辆、导弹、废弃或占位 ID。它们没有可直接采集的独立菜单图标，本次不制作替代图或冒充游戏原素材。

游戏配置还保留了实际档案不存在的引用，记录在 `missingReferences`：

- 原版：ENGINEER、SENGINEER 的 `engnuico.shp`，ORCA 的 `falcuico.shp`；NAWAST 的 `wasticon.shp`，NAPSYB 的 `psybicon.shp`。
- 尤复：ENGINEER、SENGINEER、YENGINEER 的 `engnuico.shp`，ORCA 的 `falcuico.shp`；NAPSYB 的 `psybicon.shp`。

前几项是三星图标引用，后两项为遗留建筑引用；没有因此漏掉这些普通单位图标。不以相似文件名替换缺失引用，也不把共享资源人为算成独立图标。

完整 cameo 库包含从旧游戏沿用的图标、不可生产的载机／隐藏单位素材。一些此类图标在红警调色板下颜色异常；保留游戏原数据，并将其与正常可用单位一并列明，后续制作单位榜时应按科技等级及游戏用途筛选。

## 转换与复现

运行：

```powershell
python scripts/extract-unit-icons.py
```

可用 `--game-dir` 和 `--database` 指定另一份游戏安装及 XCC 文件名数据库。输出目录固定在本项目。需要本机 Python、Pillow，以及 Python 安装自带的 OpenSSL `DLLs/libcrypto-3.dll`；没有安装新依赖或将解码库打入产品包。

`python scripts/verify-unit-icons.py` 已通过两个版本的逐图检查：原始 SHP 与来源档案字节一致，SHP／PNG 哈希与清单一致，全部帧尺寸及 RGB 格式有效，单位／建筑副本与原图一致。两个版本均没有缺失的单位普通图标引用。

MIX 索引和游戏资源解码在本地进行；SHP 按帧读取，使用 `cameo.pal` 将 6 位 RGB 通道乘 4 转为 8 位，保存为不透明 RGB PNG。菜单背景不作为透明色移除。图标尺寸与像素核对可重复执行。

格式查阅依据：[MIX](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Cnc/FileSystem/MixFile.cs)、[文件名哈希](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Cnc/FileSystem/PackageEntry.cs)、[SHP-TS](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/SpriteLoaders/ShpTSLoader.cs)。Python 提取逻辑独立编写，未把上游源文件复制进项目。
