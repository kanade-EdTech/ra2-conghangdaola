## 1. 产品目标

开发一款手机上也能轻松操作的红警 2 Tier List 生成器：选择游戏版本，把国家／阵营放入「夯、顶级、人上人、NPC、拉」五档，生成可预览、保存和分享的排名图片。

主流程：**选择版本 → 点选或拖拽分档 → 调整顺序 → 预览结果图 → 保存图片**。

首版只做国家／阵营主题，以一套离线网页核心产出两个平台包。默认打开红警 2 原版，全部项目初始位于待排名区，不预设强弱结论。默认标题为「国家强度排序」，用户可以改成实战强度、童年情怀等个人标准。改变标题只改变说明，不自动重新排序。

## 3. 功能范围与行为

### 3.1 P0：完整首版必须具备

| 功能 | 行为与验收口径 |
| --- | --- |
| 版本切换 | 原版 9 项、尤复 10 项；分别恢复榜单，不自动复制另一版本排名 |
| 卡片展示 | 中文名、阵营标识、轻量图标；选中后查看识别标签；不靠国旗 Emoji 作为唯一标识 |
| 点选分档 | 点击卡片，再选择档位，追加到该档末尾；操作面板可取消 |
| 拖拽排序 | 待排名到档位、跨档、同档重排、移回待排名；目标位置有提示 |
| 非拖拽操作 | 卡片面板提供换档、前移、后移、移回待排名；键盘和触摸均能完成核心操作 |
| 标题编辑 | 最多 30 个 Unicode 码点；按纯文本显示，不解释 HTML |
| 撤销 | 按版本保留会话内最近 20 次已提交修改；一次完整拖放只算一次 |
| 重置 | 二次确认，仅清空当前版本分档，恢复默认待排名顺序；保留标题；可撤销 |
| 本地存档 | 排名／标题变化后保存，刷新恢复；失败转内存模式，准确提示未保存 |
| 图片预览 | 从状态绘制标题、版本、五档、卡片和完成数量，保持同档顺序 |
| 未完成导出 | 允许导出，额外显示待排名区与已排 X/N，不能默默漏掉未排名项目 |
| 保存图片 | 小红书使用规定 JSBridge；Toy 按真实宿主能力验证；失败保留预览和排名 |
| 响应式布局 | 320–430px 手机与桌面可用，无页面横向溢出，处理底部安全区 |
| 双平台交付 | 两套静态目录及 ZIP，根入口均为 index.html，业务资源全部本地化 |

补充规则：同档顺序从左到右、从上到下；移回待排名追加到末尾；重置才恢复默认名单顺序。取消操作或无位置变化的拖放不进入撤销历史。两个版本的标题、排名和撤销历史独立。

### 3.2 P1：首版后增加

- 自定义档名、副标题、每国一句评语；多张本地命名榜单。
- 横版／竖版导出模板，小红书可增加 3:4 版式。
- 经真机验证后增加「带图去发笔记」，仅在用户主动点击时调用。
- 文本分享码导入／导出；小红书使用可选择文本和手动粘贴，不依赖剪贴板 API 或 JSON 文件选择。

### 3.3 暂不包含

兵种、建筑、地图、英雄与 MOD 排名；在线投票、公共排行榜、登录、云同步、后台管理、跨平台账号互通、游戏数值模拟、默认音乐和开场视频。

## 4. 界面与操作设计

```text
红警 2 · 从夯到拉
[红警 2 原版] [尤里的复仇]
榜单标题：[国家强度排序]

夯     | 卡片 卡片 …
顶级   | 卡片 …
人上人 | 卡片 …
NPC    | 卡片 …
拉     | 卡片 …

待排名 X/N
国家卡片网格
[撤销] [重置] [生成结果图]
```

手机纵向布局，档位标签约 56–64px 宽，卡片自动换行；桌面可把待排名区放在侧栏。空档使用轻提示，不占过高空间。

视觉采用深灰作战台、克制的金属边框、红色强调和五档色条。盟军／苏军／尤里用蓝／红／紫小标识，避免抢占档位颜色。排名和名称是视觉中心，不使用持续闪烁、粒子或背景视频。

图标优先原创几何徽记或项目内明确可使用的图片；素材未齐时用名称与文字徽记完成应用。素材清单记录来源和使用说明，首版不捆绑原版音乐、视频或游戏安装文件。

手机交互要求：

- 点选分档始终可用；卡片设置明确拖拽手柄，只在局部控制 touch-action，其他区域正常滚动。
- 优先 Pointer Events，缺失时提供 Touch／Mouse 回退；处理 pointercancel、拖出容器和触摸取消。
- 拖动边缘有限速自动滚动，松手提交一次，取消恢复原位置。
- 热区至少 44×44 CSS px；核心操作不依赖 hover；按钮焦点可见。
- 弹层管理焦点，关闭后回到触发项；卡片提供不依赖拖拽的顺序按钮。
- 底栏预留内容空间，不能盖住最后一行；标题输入时处理软键盘。安全区先提供普通值回退，再使用容器变量与 env()。

## 5. 技术方案

### 5.1 选型

当前仓库只有说明文件，没有前端构建链。推荐 **HTML + CSS + 原生 JavaScript（ES2017）+ Canvas 2D**，用轻量脚本复制静态文件、选择平台适配器并打包。

10 个条目无需大型 UI 框架、拖拽库、DOM 截图库或通用状态管理。源码按职责拆分成经典脚本，通过一个应用命名空间协作，HTML 明确依赖顺序；排名逻辑独立为可测试函数。

经典脚本是小红书离线容器约束。若后续引入构建工具，必须产出 Chrome 61 可运行的经典脚本，并检查最终 HTML；仅设置相对 base 或 JS target 不足以满足要求。

开发期 Node／Python 脚本不随包运行。没有 Node 时可使用现有 Python／PowerShell 打包，不为复制静态文件安装整套工具链。若增加开发依赖，实施时核对本机兼容版本并锁定。

### 5.3 数据契约

国家字段：id、name、faction、versions、signature、iconPath；图片失败用文字徽记。版本使用 ra2／yr，阵营使用 allied／soviet／yuri。小型名单随经典脚本加载，不能通过 fetch('./countries.json') 读取。

存档键建议为 `ra2-tier-list:save:v1`，结构示例：

```json
{
  "schemaVersion": 1,
  "activeVersion": "ra2",
  "boards": {
    "ra2": {
      "title": "国家强度排序",
      "tiers": { "hang": [], "top": [], "elite": [], "npc": [], "la": [] },
      "unranked": ["america", "britain", "france", "germany", "korea", "russia", "iraq", "cuba", "libya"]
    },
    "yr": {
      "title": "国家强度排序",
      "tiers": { "hang": [], "top": [], "elite": [], "npc": [], "la": [] },
      "unranked": ["america", "britain", "france", "germany", "korea", "russia", "iraq", "cuba", "libya", "yuri"]
    }
  }
}
```

必须维护的不变量：

1. 每个有效 ID 恰好出现在一个档位或待排名区。
2. 五档与待排名的 ID 并集等于版本允许集合，既不重复也不遗漏。
3. 原版不能出现 yuri；切换版本不改变另一版本榜单。
4. 移动先计算完整下一状态，通过校验后一次提交并渲染。
5. 撤销历史仅存内存，按版本隔离，不记录每个拖动帧。

读存档捕获异常并校验字段类型与 schemaVersion。已知格式清除未知 ID、按固定档位次序去重，把缺失的有效 ID 补到待排名末尾。格式不可修复时保留原始内容或不覆盖原键，以新内存状态启动并提示；未知高版本不能静默覆盖。

保存采用小幅防抖，并在版本切换、生成图片和页面隐藏前尝试落盘。写入异常不影响使用。两个平台本地存档彼此独立，缓存不保证永久保存，也不提供跨平台同步。

### 5.4 平台边界

业务层通过项目内部接口请求保存草稿、展示预览、保存图片，平台适配器实现差异。这些内部接口不是平台 SDK 方法名。

构建时只放入当前平台适配器，避免小红书包残留浏览器下载、剪贴板或联网代码。Toy 首版不依赖云存储／排行榜 SDK；后续接入需先读当时官方文档。

## 6. 双平台约束

小红书要求依据本机 minitool-zip-builder v1.6.0 及 references，作为当前开发基线；发布前再核对最新平台要求。

| 项目 | 小红书小工具 | B 站 Toy |
| --- | --- | --- |
| 入口 | ZIP 根目录直接含 index.html | 本项目同样用根入口 |
| 路径 | 所有资源包内相对引用 | 相对引用，兼容 /toy/<slug>/ 子路径 |
| 联网 | 禁止网络请求及外部资源 | 首版业务资源全部本地化 |
| 脚本 | 外置经典脚本，ES2017／Chrome 61 | 复用核心，平台增强隔离 |
| 页面 | 单 HTML 内切换视图 | 单页即可，不用 history 路由 |
| 保存草稿 | 本地存储，异常降级 | 本地存储，在真实入口验证恢复 |
| 图片保存 | 规定 JSBridge | 按宿主能力验证，不能假定 App 等同桌面浏览器 |
| 下载 | 禁止 a[download] 与 blob 下载 | 浏览器可尝试下载，App 不支持则预览／截图 |
| 剪贴板、长按 | 不依赖剪贴板 API 或系统长按菜单 | 不作为核心前提 |
| 包体 | 当前参考门禁 ≤10 MiB，目标 ≤2 MiB | 不写死未核实上限，项目同样争取 ≤2 MiB |

Toy 子路径与发布前检查依据官方维护的 CLI 文档；实际提交时再核对最新版。[Toy 官方内容检查清单](https://github.com/bilibili/toy/blob/main/skills/toy/references/content-checklist.md)

小红书最终包不得包含内联 JS、行内事件、eval、new Function、WASM、iframe／object、Worker、Service Worker、外链跳转、联网调用、运行时模块导入；不能自行添加 CSP meta 或 base。原生桥只用文档列出的 window.xhs.miniTool.*。

CSS 使用 Chrome 61 基线：Flex 间距用 margin；gap、aspect-ratio、clamp、动态视口单位等不能作为唯一实现。visualViewport 等能力需检测后使用。新版浏览器通过不能代替旧内核实测。

## 7. 图片导出

使用 **Canvas 2D 根据状态重新排版**，不截取页面 DOM，避免滚动、工具栏和弹层影响结果。

- 默认宽 1080px，高度按标题、卡片行数和待排名区计算，并限制最大画布像素预算。
- 等待本地图标加载；失败回退文字徽记，不阻塞整图。
- 标题按实际文字宽度换行，国家名完整显示；空档保留。
- 包含标题、版本、五档和已排数量；未完成时保留待排名区。
- 图底可写「个人游戏体验，仅供交流」，不伪造平台标识或作品链接。
- 捕获分配、绘制和序列化失败，提供较低分辨率重试。
- 生成图只临时驻留，不把 Base64 写入源码或长期存档；关闭预览释放内存和对象 URL。

小红书保存流程：

```text
用户点击保存图片
→ 检测 window.xhs.miniTool.writeTempFile / saveImageToPhotosAlbum
→ canvas.toDataURL('image/png') 获取完整 data:uri
→ writeTempFile({ data }) 返回 filePath
→ saveImageToPhotosAlbum({ filePath })
→ 成功后提示；失败保留预览并允许重试
```

不得去掉 data:uri 前缀或把网络 URL 当本地路径。Bridge 不存在时展示预览并提示系统截图；小红书系统长按菜单受限，不能以「长按保存」兜底。Toy 保存行为待真实预览页验证；发起下载不等于确认保存成功。

## 8. 开发阶段与预估

按一名开发者全职、采用轻量自制素材估算约 **6–8 个工作日**，另加审核等待时间；这是排期估算，不是完成承诺。

| --- | --- | --- | --- |
| M0 兼容性小样与资料定稿 | 0.5 天 | 最小页面、名单、保存试验记录 | 优先检查脚本、离线资源、Canvas 与 Bridge；缺真机明确待验 |
